# OpsAgent 测试手册

> 目的：明确"什么叫测试通过"。每次提交推送前都按本手册走一遍，测试通过才推送。

## 一、四层测试

| 层次 | 查什么 | 用什么工具 |
| --- | --- | --- |
| 1. 编译检查 | 代码能不能编译通过（语法、依赖、注解） | 命令行跑 Maven |
| 2. 启动检查 | 应用能否正常启动、能否连上数据库 | IDEA 里 Run |
| 3. 接口验证 | 接口是否返回预期结果，异常情况是否有正确提示 | PowerShell / 浏览器 |
| 4. 数据验证 | 数据是否真的正确落库 | Navicat / 命令行 |

## 二、第 1 层：编译检查

Windows CMD 中执行（用 IDEA 自带的 Maven，不需要单独安装）：

```cmd
cd /d C:\Users\86132\projects\opsagent\backend
```

```cmd
"D:\IntelliJ IDEA 2024.2.6\plugins\maven\lib\maven3\bin\mvn.cmd" compile
```

**正确输出**：最后出现

```text
[INFO] BUILD SUCCESS
```

**错误输出**：出现 `[ERROR]` 与 `BUILD FAILURE`，并在前面指出文件和行号，例如：

```text
[ERROR] /C:/Users/.../ServerController.java:[21,8] cannot find symbol
```

## 三、第 2 层：启动检查

IDEA 中打开 `OpsAgentApplication`，点绿色三角或按 `Shift + F10`。

**正确输出**（Run 面板最后几行）：

```text
Tomcat started on port 8080
Started OpsAgentApplication in 3.2 seconds
```

**错误输出对照表**：

| 报错关键字 | 含义 |
| --- | --- |
| `APPLICATION FAILED TO START` | 启动失败，下方会写明原因 |
| `Communications link failure` / `Connection refused` | 连不上数据库（虚拟机没开机、容器没启动、IP 变了） |
| `Access denied for user` | 数据库账号或密码不对 |
| `Table 'opsagent.xxx' doesn't exist` | 表没建，需要执行建表脚本 |
| `Port 8080 was already in use` | 端口被占用，上次的服务还在运行 |

## 四、第 3 层：接口验证

### 4.1 健康检查

浏览器访问：

```text
http://localhost:8080/api/health
```

**正确输出**：

```json
{"status":"UP","service":"opsagent-backend","time":"2026-09-13T..."}
```

### 4.2 服务器列表（验证能不能从数据库读到数据）

```text
http://localhost:8080/api/servers
```

**正确输出**：数组里有 `ubuntu-vm`，且 `description` 是正常中文：

```json
[{"id":1,"name":"ubuntu-vm","host":"192.168.169.129","port":22,"status":"ONLINE",
  "os":"Ubuntu 24.04 LTS","description":"本项目的被监控服务器（VMware 虚拟机）"}]
```

如果看到 `æœ¬é¡¹ç›®` 这类字符，说明字符集又出问题了，检查 `SET NAMES utf8mb4` 和 JDBC 连接串。

### 4.3 注册接口（POST 请求）

浏览器地址栏只能发 GET 请求，POST 用 PowerShell：

```powershell
Invoke-RestMethod -Uri "http://localhost:8080/api/auth/register" -Method Post -ContentType "application/json" -Body '{"username":"testuser","password":"test123","nickname":"测试用户"}'
```

**正确输出**：

```text
success message  data
------- -------  ----
   True 注册成功 @{id=2; username=testuser; nickname=测试用户; role=VIEWER}
```

**重复注册同一个用户名**（再执行一次同样的命令）应当返回：

```text
success message      data
------- -------      ----
  False 用户名已存在
```

注意返回的 `data` 里**没有 password 字段**，这是刻意设计。

### 4.4 登录接口

密码正确：

```powershell
Invoke-RestMethod -Uri "http://localhost:8080/api/auth/login" -Method Post -ContentType "application/json" -Body '{"username":"testuser","password":"test123"}'
```

**正确输出**：`success = True`，`message = 登录成功`。

密码错误：

```powershell
Invoke-RestMethod -Uri "http://localhost:8080/api/auth/login" -Method Post -ContentType "application/json" -Body '{"username":"testuser","password":"wrong123"}'
```

**正确输出**：`success = False`，`message = 用户名或密码错误`。用户名不存在时也必须是同一句提示。

## 五、第 4 层：数据验证

用 Navicat 连接（主机 `192.168.169.129`、端口 `3306`、用户 `root`、密码 `opsagent123`），查看 `sys_user` 表：

| 字段 | 期望值 |
| --- | --- |
| username | 刚注册的用户名 |
| password | `$2a$10$` 开头的 60 位字符串（BCrypt 哈希，不是明文） |
| role | 新用户默认 `VIEWER` |
| status | 1 |

也可以在虚拟机里用命令行查：

```bash
docker exec opsagent-mysql mysql --default-character-set=utf8mb4 -uroot -popsagent123 -e "SELECT id, username, role, LEFT(password, 7) AS pwd_prefix FROM opsagent.sys_user;"
```

`pwd_prefix` 应当都是 `$2a$10$`。

## 六、每次提交前的固定动作

1. 第 1 层编译检查通过；
2. 第 2 层启动无报错；
3. 第 3 层相关接口返回符合预期（包括错误场景）；
4. 第 4 层数据库里的数据正确；
5. 然后才执行 `git add` / `git commit` / `git push`。

任何一层不通过，先修问题，不推送。
